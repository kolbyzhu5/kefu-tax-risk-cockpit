## 五、缺陷清单（v1.1 已全部修复）

### 🔴 D1（P1 · Major）金额规模因子实现偏离方案分段口径 — ✅ 已修复

- **位置**：`server/src/engine/scoring.ts` → `amountScaleFactor()`
- **方案**（4.2）：分段离散 `<100万=0.6 / 100–1000万=0.8 / 1000–5000万=1.0 / >5000万=1.2`
- **实现**：连续线性 `clamp(0.6 + amountWan/2000, 0.6, 1.2)`
- **实测偏差**：100万→0.65(应为0.8)、1000万→1.1(应为1.0)、3000万→1.2(应为1.0)、5000万→1.2(正确)
- **影响**：当前未接线到总分（L2 用硬编码 scores），**无即时影响**；但作为 L1 核心公式，接真实数据时会系统性偏离口径。
- **修复（v1.1）**：✅ 改为分段阶梯函数（`<100→0.6 / 100~1000→0.8 / 1000~5000→1.0 / ≥5000→1.2`），边界回归 10/10 通过。

### 🔴 D2（P1 · Major）SLA 逾期加成未分档 — ✅ 已修复

- **位置**：`scoring.ts` → `slaOverdueAdjust()`
- **方案**（4.6）：高危 >7 天未核实 +10；中危 >30 天未整改 **+5**
- **实现**：命中即统一返回 **+10**，未区分档位
- **影响**：模型页「动态修正因子」当前显示 `sla=+10`，中危逾期场景会高估 5 分。
- **修复（v1.1）**：✅ 改为分档（高危>7天未核实 +10 / 中危>30天未整改 +5，取最高档），回归 2/2 通过。

### 🟡 D3（P2 · Minor）重复疑点聚合缺失「同一主体」维度 — ✅ 已修复

- **位置**：`scoring.ts` → `repeatAggregationAdjust()`
- **方案**（4.6）：「同一主体 + 同类 ≥3 条」触发 +15
- **实现**：仅按 `catCode` 计数 ≥3，忽略 `sub_id`
- **影响**：模拟数据下发票类 4 条（分属 4 个不同主体）被误判为「系统性风险 +15」；按方案口径应为 0（无同主体同类 ≥3）。
- **修复（v1.1）**：✅ 增加 `subId` 维度，按 `subId:catCode` 组合计数，回归 2/2 通过（模拟数据 repeat 归 0，符合方案口径）。
