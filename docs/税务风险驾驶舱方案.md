## 一、项目概述与设计目标

**定位**：这是集团「业—财—税—资—档」一体化数智经营驾驶舱中，**税务域的风险专题看板**。它把集团及下属子公司的税务风险从「事后发现、人工排查」升级为「实时识别 → 分级 → 处置跟踪 → 穿透取证」的闭环。

**核心设计目标（4 条）**：
1. **一屏看全**：集团税务风险总分、风险结构、子公司排名，3 秒建立全局认知。
2. **风险可切**：按 5 大风险分类（发票 / 收入成本 / 优惠 / 关联交易 / 个税社保）横向切片。
3. **处置可追**：每个疑点有明确状态（待核实 → 整改中 → 已销号）与责任人闭环。
4. **证据可溯**：任何疑点一键下钻到原始凭证、发票、合同、资金流水，支撑金税四期「三流一致」自证。

**闭环逻辑**：

```
风险识别 → 风险分级 → 处置跟踪 → 穿透取证 → 销号复核
   │           │           │           │
   └── 分类视图 ── 总览KPI ── 处置看板 ── 下钻明细
```

## 四、风险评分模型（五类加权聚合 · v0.2 深化）

### 4.1 四层计算架构

评分自下而上逐层聚合，任意一层都可穿透回底层疑点：

```
L1 疑点层   18 个原子疑点（等级 × 金额 × 状态 → 疑点贡献分）
   │  按分类聚合
L2 分类层   5 类风险得分（基础分 + 疑点增量分）
   │  按权重 25/20/15/20/20 加权
L3 子公司层 6 家子公司风险得分（Σ 分类得分 × 权重）
   │  按营收加权
L4 集团层   集团总风险得分（Σ 子公司得分 × 营收权重）
```

### 4.2 L1：疑点贡献分

```
疑点贡献分 = 等级基础分 × 金额规模因子 × 状态因子
```

| 因子 | 取值规则 |
|---|---|
| 等级基础分 | 高 = 100 / 中 = 60 / 低 = 30 |
| 金额规模因子 | <100 万 = 0.6；100–1000 万 = 0.8；1000–5000 万 = 1.0；>5000 万 = 1.2 |
| 状态因子 | 待核实 = 1.0；整改中 = 0.9；已销号 = 0.2（已处置降权，不归零以留痕） |

### 4.3 L2：分类得分

```
分类得分 = 基础分 + 疑点增量分（截断至 [0,100]）
基础分    = 该分类固有基线风险（即使无活跃疑点也存在，如优惠类约 15–20 分）
疑点增量分 = Σ(该分类活跃疑点贡献分) 的金额加权归一
```

> 设计要点：基础分体现「无显性疑点 ≠ 零风险」——合规维护本身存在固有风险敞口；疑点增量分体现「显性风险暴露」。这解释了原型中「建工建设无优惠疑点但优惠得分 20 分」的现象。

### 4.4 L3：子公司得分

```
子公司得分 = Σ(分类得分ᵢ × 权重ᵢ)
```

以建工建设为例（权重 25/20/15/20/20）：

| 分类 | 得分 | 权重 | 加权 |
|---|---|---|---|
| 发票 | 55 | 25% | 13.75 |
| 收入成本 | 68 | 20% | 13.60 |
| 优惠 | 20 | 15% | 3.00 |
| 关联交易 | 45 | 20% | 9.00 |
| 个税社保 | 65 | 20% | 13.00 |
| **合计** | | | **52.35 ≈ 52.4** |

### 4.5 L4：集团总分（营收加权）

```
集团总分 = Σ(子公司得分ᵢ × 营收ᵢ) ÷ Σ(营收ᵢ)
```

> 营收加权使「大营收主体」对集团总分影响更大——高营收子公司（建工 80 亿）的风险比小营收子公司（云启 12 亿）更应拉高集团总分。营收权重可在投产时切换为「利润加权」「资产加权」或「等权」。

**五类风险权重**（合计 100%，权重对应税务稽查重点频次）：

| 风险分类 | 权重 | 核心风险点（金税四期口径） |
|---|---|---|
| 发票风险 | 25% | 虚开/接受虚开、三流不一致、异常红冲、进项转出遗漏 |
| 收入成本风险 | 20% | 隐匿收入、视同销售漏报、成本结转与进度不匹配 |
| 优惠政策风险 | 15% | 高新/小微/研发加计资质真实性、条件持续满足 |
| 关联交易风险 | 20% | 转让定价、同期资料、关联资金占用 |
| 个税社保风险 | 20% | 个税全员申报、社保基数、专项附加扣除 |

**风险分级（对齐税务风控评分口径）**：

| 区间 | 等级 | 色 | 处置要求 |
|---|---|---|---|
| 0 – 30 | 低 | 绿 | 常规监控 |
| 31 – 60 | 中 | 橙 | 限期整改（≤30 天） |
| 61 – 100 | 高 | 红 | 立即核实 + 标红上报（≤7 天） |

### 4.6 动态修正因子（v0.2 新增）

静态评分之外，叠加三类动态修正，使总分随处置进度「活」起来：

| 因子 | 规则 | 作用 |
|---|---|---|
| SLA 逾期加成 | 高危 >7 天未核实 +10 分；中危 >30 天未整改 +5 分 | 处置拖延推高风险分 |
| 时间衰减 | 已销号疑点 180 天后移出活跃计分 | 避免历史风险永久拉高总分 |
| 重复疑点聚合 | 同一主体同类疑点 ≥3 条，触发「系统性风险」+15 分 | 识别重复违规模式 |

### 4.7 权重校准机制（投产前）

权重与阈值不是一次定稿，而是持续校准：

1. **AHP 层次分析法**：税务专家对 5 类风险两两比较，构造判断矩阵求权重，一致性检验 CR<0.1。
2. **德尔菲法**：多轮匿名专家打分收敛，消除个体偏差。
3. **回溯校验**：用历史稽查案例回测评分模型的命中率与误报率，反向调权。
4. **月度重校**：权重随监管口径（金税四期风险点频次）月度复盘微调。

> 说明：以上为**设计口径（模拟）**。分类得分由「基础分 + 疑点增量分」构成，疑点增量分 = 该类疑点贡献分的金额加权归一。正式投产须由税务风控专家校准权重、基础分与阈值。

### 5.4 下钻血缘与穿透取证（v0.2 深化）

下钻不是简单跳表，而是一条**可追溯的数据血缘链**：从疑点定位到命中规则，再回溯到支撑该疑点的四类证据与源系统字段。

#### 5.4.1 数据血缘五层链路

```
源系统层  ERP · 税务申报 · 司库 · 电子档案 · 合同台账 · 个税系统
   │ 抽取
ODS 层    贴源原始数据（不动结构，保真）
   │ 清洗 / 标准化
数仓层    DWD 明细（凭证/发票/合同/流水事实表）+ DIM 主数据（客商/组织/科目）
   │ 规则计算
引擎层    风险规则引擎（阈值/勾稽/三流一致）→ 命中即生成疑点
   │ 服务
看板层    5 视图 + 下钻（点疑点 → 反查四类证据明细）
```

#### 5.4.2 主数据关联键（下钻的血缘锚点）

疑点能穿透到四类证据，依赖一套**统一主数据键**，把「账 / 票 / 合同 / 资金」串起来：

| 主数据键 | 说明 | 串联对象 |
|---|---|---|
| sub_id | 组织机构 / 子公司编码 | 所有事实表分区键 |
| vendor_id | 客商编码（对手方） | 合同 · 发票 · 流水 |
| contract_no | 合同编号 | 合同 → 发票 → 流水 |
| invoice_no | 发票号码 | 发票 → 凭证 → 流水 |
| voucher_no | 凭证号 | 凭证 → 发票 |
| bank_seq | 银行流水号 | 流水 → 发票 / 合同 |

#### 5.4.3 三流一致交叉核验规则（疑点生成引擎核心）

| 核验维度 | 规则 | 偏差阈值 | 命中疑点示例 |
|---|---|---|---|
| 合同 vs 发票 | \|合同金额 − 发票金额\| ÷ 合同金额 | >5% | 分包发票三流不一 |
| 发票 vs 资金 | \|发票金额 − 付款金额\| ÷ 发票金额 | >10% | 疑似接受虚开专票 |
| 凭证 vs 发票 | 进项税额 vs 发票税额 | 不一致 | 进项转出遗漏 |
| 申报 vs 财报 | \|申报收入 − 财报收入\| ÷ 财报收入 | >5% | 隐匿收入 |

#### 5.4.4 各风险类型 → 证据组合映射

| 风险分类 | 必看证据（主） | 辅助证据 | 核验要点 |
|---|---|---|---|
| 发票风险 | 发票 + 凭证 + 资金流水 | 合同 | 三流一致、进项转出 |
| 收入成本风险 | 凭证 + 合同 + 发票 | 资金流水 | 确认时点、勾稽差异 |
| 优惠政策风险 | 凭证 + 合同 + 资质申报 | 流水 | 资质真实性、条件满足 |
| 关联交易风险 | 合同 + 资金流水 + 同期资料 | 凭证 | 转让定价、资金占用 |
| 个税社保风险 | 凭证(工资表) + 资金流水 + 申报表 | 合同 | 全员申报、基数一致 |

#### 5.4.5 下钻取数逻辑（点击 → 证据回显）

```
① 点击疑点（含 sub_id + 疑点类型 + 关联键）
② 引擎反查命中该疑点的规则及其阈值
③ 按主数据键从 DWD 四类事实表取明细（凭证/发票/合同/流水）
④ 前端弹窗分 Tab 回显，标注「三流一致」核验结论
⑤ 留痕：每次下钻生成审计日志（谁、何时、看了哪条证据）
```

#### 5.4.6 证据字段（沿用原型，对齐金税四期）

| 证据类型 | 关键字段 | 对应「三流」 |
|---|---|---|
| 原始凭证 | 凭证号 / 日期 / 科目 / 摘要 / 金额 | 账流 |
| 发票 | 发票号码 / 开票方 / 金额 / 税率 / 用途确认 | 票流 |
| 合同 | 合同编号 / 签约方 / 金额 / 签订日期 | 合同流 |
| 资金流水 | 流水号 / 对手方 / 金额 / 交易日期 | 资金流 |

> 下钻的证据字段对齐金税四期「合同—发票—资金」三流一致穿透逻辑，便于税务稽查时自证业务真实性。

## 七、指标口径与预警规则（对齐现行法规口径）

| 指标 | 公式 | 预警阈值（经验基线） |
|---|---|---|
| 增值税税负率 | 应纳增值税 ÷ 不含税收入 | 制造业 2.5–4.5%、商贸 0.8–2.5%、建筑 1.5–3%、软件 3–6%、现代服务 2–6%，偏离 ±1pct 预警 |
| 所得税税负率 | 应纳所得税 ÷ 收入 | 偏离行业均值预警 |
| 毛利率 | (收入 − 成本) ÷ 收入 | 低于行业下限预警（隐匿收入线索） |
| 费用率 | 期间费用 ÷ 收入 | 异常波动预警 |
| 收入勾稽差异 | \|税务申报收入 − 财报收入\| ÷ 财报收入 | > 5% 预警（金税四期重点） |

**引用依据（设计参考，正式投产须实时核验）**：
- 《增值税法》（主席令第四十一号，2026-01-01 施行）
- 《企业所得税法》（主席令第二十三号，2018 修正）
- 《税收征收管理法》（主席令第二十三号，2015 修正）
- 金税四期「以数治税」票货资金人员账多维比对逻辑

## 八、实施路线图（v0.2 深化 · 供讨论）

整体分 5 阶段，约 **14–20 周（3.5–5 个月）**，P0 先行，P1–P3 可部分并行。

| 阶段 | 周期 | 关键任务 | 里程碑 / 交付物 | 验收标准 |
|---|---|---|---|---|
| P0 指标与数据架构 | 2–3 周 | 主数据梳理；评分权重 AHP 校准；指标字典定稿 | 指标字典 v1.0 + 评分模型 v1.0 | 权重一致性 CR<0.1；指标口径税务部会签通过 |
| P1 数据集成 | 4–6 周 | 对接 ERP/税务申报/司库/电子档案/合同台账/个税系统；ODS→DWD→DIM 建仓；主数据治理 | 数据底座上线 + 主数据清单 | 五源系统可自动抽取；关键字段完整率 >95% |
| P2 预警与决策引擎 | 3–4 周 | 阈值规则配置；三流一致核验引擎；SLA 逾期 / 派单 | 预警引擎 v1.0 | 规则命中准确率回测达标；疑点可自动生成 |

### 8.3 关键风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 主数据不统一（客商/合同/发票编码缺失） | 下钻血缘断链 | P0 优先做主数据治理，先治理再集成 |
| 源系统数据质量差 / 口径不一 | 疑点误报 | P1 建数据质量看板，设完整率 / 一致率阈值 |

3. 本方案不构成税务 / 法律 / 审计鉴证意见；重大涉税事项建议咨询持证专业人士。
